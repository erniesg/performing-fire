# Add social share metadata and a favicon to every page

depends-on: 002

## Goal

The site has no meta descriptions, Open Graph/Twitter cards, canonical URLs, or favicon — links shared to social platforms and chat apps render bare. Add complete share metadata to `public/index.html`, `public/broadcast.html`, and `public/experiments/index.html`, plus an inline-SVG favicon consistent with the CRT/fire identity. Everything stays static and self-contained: the OG image must be a checked-in asset under `public/`, not a remote URL or a generation service.

## Acceptance tests

- Each of the three pages has: `<meta name="description">` (unique per page), `og:title`, `og:description`, `og:type`, `og:url` (absolute `https://performingfire.berlayar.ai/...`), `og:image` (absolute URL pointing at a checked-in `public/share/og.png` — new directory; ≤ 250 KB, 1200x630), `twitter:card` = `summary_large_image`, and `<link rel="canonical">`. A new test `tests/meta.test.mjs` (new file) asserts all of these per page.
- A favicon exists as `public/favicon.svg` (new, hand-authored SVG — a minimal CRT/flame mark using the phosphor palette, no raster tooling required) and each page links it via `<link rel="icon" type="image/svg+xml">`; the test asserts the link and that the SVG parses as XML.
- The OG image may be generated by any locally-runnable means; if no image tooling is available in the sandbox, create `public/share/og.svg` as the source of truth, reference it from a `README` line in `public/share/`, mark the PNG as pending in the PR body, and make the test accept either the PNG or (temporarily) the SVG with a TODO marker — do not fetch remote services.
- `npm test` fully green; existing tests untouched.

## Stop conditions

- Stop if an approach would require fetching fonts, images, or APIs at build/run time.
- Do not add analytics, tracking pixels, or third-party embeds — this issue is metadata only.
- Never modify `docs/` or `tmp/`.

## Human clarification protocol

Comment with the proposed description copy for the three pages (EN with KO accents, matching the site voice) and one recommendation; proceed with placeholder-free best-effort copy if no reply.

## Recommended response

Approve the metadata set and favicon; iterate on the OG image art in a follow-up if the first pass is too plain.

## Trade-offs

A checked-in static OG image is less flexible than a generator but keeps the site dependency-free and the deploy surface unchanged; per-locale share copy is deferred until the i18n dictionaries stabilize.
